# LLM Evaluation Pipeline – Qualitative Scoring

This pipeline supports the **qualitative evaluation of model-generated answers**, using GPT to score each response across five expert-level criteria inspired by [HealthBench](https://openai.com/index/healthbench/).

---

## 🔁 Pipeline Overview

This qualitative scoring pipeline should be run **after** the benchmarking phase, where your models generate `merged_answers.jsonl` files (containing the model's answer and `index` information per GMAI-MMBench entry).

The flow is as follows:

1. **Benchmarking Phase**  
   → Run inference and generate `cleaned_answers.jsonl` per model.

2. **Qualitative Judgment Phase (this pipeline)**  
   → Evaluate response quality using LLM scoring over 5 HealthBench-style criteria.

---

## Script Overview

###  `make_batches_eval.py`

**Purpose**: Prepares batch requests to evaluate the **quality of model explanations** based on:

- `accuracy`: Are clinical facts correct?
- `completeness`: Does the answer address all essential elements?
- `instruction_following`: Is the model aligned with the user's prompt?
- `communication`: Is the answer clearly written and well-structured?
- `context_awareness`: Does it reflect broader clinical context when relevant?

Each response is scored from 1 to 5.

* Uses: `cleaned_answers.jsonl` + base64-encoded images from `GMAI-MMBench_VAL.tsv`
* Outputs: `batches_eval/`

**Run with:**

```bash
nohup python make_batches_eval.py > logs/make_batches_eval.log 2>&1 &
```

---

###  `make_api_queries.py` (same file, with updated paths)

**Purpose**: Sends qualitative evaluation requests in `batches_eval/` to OpenAI and stores batch IDs in `output_eval_judge/`

**Run with:**

```bash
nohup python make_api_queries_eval.py > logs/make_api_queries_eval.log 2>&1 &
```

---

###  `dataset_remaker_eval.py`

**Purpose**: Retrieves the **scores** from OpenAI and extracts a dictionary of 5 numerical values.

* Reads batch IDs from: `output_eval_judge/`
* Output: `final_judgment_scores.jsonl`, format:

```json
{
  "custom_id": "request-42",
  "scores": {
    "accuracy": 5,
    "completeness": 4,
    "instruction_following": 5,
    "communication": 4,
    "context_awareness": 3
  }
}
```

**Run with:**

```bash
nohup python dataset_remaker_eval.py > logs/dataset_remaker_eval.log 2>&1 &
```

### `merge_scored_answers.py`

**Purpose**: Merges the GPT-generated scores into each corresponding answer entry using custom_id.

* Inputs:
- merged_answers.jsonl
- final_eval.jsonl
* Output:
- merged_scored_answers.jsonl (per model, with both answer and evaluation scores)

Run with:
```bash
python merge_scored_answers.py
```

### `summarize_eval_scores.py``

**Purpose**: Computes and visualizes average scores per criterion per model.

* Inputs: merged_scored_answers.jsonl from all models
* Outputs:
- score_summary.csv → Average scores table
- score_radar_plot.png → Radar chart comparing models


Run with:
```bash
python summarize_eval_scores.py
```

---
## Adding New Models

To evaluate additional models, simply:

1. **Add their paths** to the list at the top of the following scripts:
   - `make_batches_eval.py`
   - `dataset_remaker_eval.py`
   - `merge_scored_answers.py`
   - `summarize_eval_scores.py`

2. **Ensure the expected files are present for each model:**
   - `merged_answers.jsonl` → output from the benchmarking pipeline
   - `final_eval.jsonl` → will be generated by `dataset_remaker_eval.py`
   - `merged_scored_answers.jsonl` → will be generated by `merge_scored_answers.py`

Once added, the pipeline will automatically include all models in the evaluation and comparison steps.
