# LLM Comparison Pipeline – Pairwise Model Preference (GPT-4 Judge)

This pipeline enables direct pairwise comparison between two LLMs (e.g., Gemma vs Qwen) on multimodal medical questions using GPT-4o as an automated judge. It supports comparison based on response quality, and outputs model preferences at scale.

---

## 🔁 Pipeline Overview

This comparison pipeline is intended to be run **after** the benchmarking phase, where your models generate `cleaned_answers.jsonl` files (containing the model's answer and `index` information per GMAI-MMBench entry).

The flow is as follows:

1. **Benchmarking Phase**  
   → Run inference and generate `cleaned_answers.jsonl` per model.

2. **Input Preparation Phase**  
   → Build pairwise prompts using both models’ answers + image reference.

3. **Comparison via OpenAI APIe**  
   → GPT-4o receives both answers (anonymized) and judges which is better, based on a 5-criteria framework.

4. **Extraction + Visualization**  
   → Final preferences are saved and visualized by clinical group.

---

## Script Overview

###  `make_batches.py`

**Purpose**: Creates pairwise comparison prompts for GPT-4o. For each question, two model responses (Response A and Response B) are presented with the corresponding medical image.

* Uses: 
   * `cleaned_answers.jsonl`
   * `GMAI-MMBench_VAL.tsv`  for metadata
   * file_map.json for mapping image index → OpenAI file_id
* Outputs: `batches_comparison/gemma_vs_qwen/part_*.jsonl`

**Run with:**

```bash
nohup python make_batches.py > logs/make_batches.log 2>&1 &
```

---

###  `make_api_queries.py` (same file, with updated paths)

**Purpose**: Sends qualitative evaluation requests in `batches_comparison/` to OpenAI and stores batch IDs in `output_comparison/`

**Run with:**

```bash
nohup python make_api_queries.py > logs/make_api_queries.log 2>&1 &
```

---

###  `dataset_remaker.py`

**Purpose**: Retrieves the GPT-4o judgment outputs and extracts the preferred model per question..

* Reads batch IDs from: `output_comparison/gemma_vs_qwen/`
* Output: `final_comparison.jsonl`, format:

```json
{
  "custom_id": "request-42",
  "preferred_model": "model_a",
  "full_response": {...}
}
```

**Run with:**

```bash
nohup python dataset_remaker.py > logs/dataset_remaker.log 2>&1 &
```

### `merge_comparison.py`

**Purpose**: Merges the GPT-generated scores into each corresponding answer entry using custom_id.

* Inputs:
- merged_answers.jsonl
- final_eval.jsonl
* Output:
- merged_scored_answers.jsonl (per model, with both answer and evaluation scores)

Run with:
```bash
python merge_comparison_answers.py
```

### `visualize_comparison_results.py``

**Purpose**: Generates heatmaps of model preference by clinical groupings:

* Inputs: `final_comparison.jsonl` + `GMAI-MMBench_VAL.tsv`
* Outputs: 
PNG heatmaps in `visualizations/heatmaps_by_group/`


Run with:
```bash
python visualize_comparison_results.py
```

## Adding New Models

To evaluate additional models, simply:

1. **Add their paths** to the list at the top of the following scripts:
   - `make_batches.py`
   - `dataset_remaker.py`
   - `merge_scored_answers.py`
   - `visualize_comparison_results.py`

2. **Ensure the expected files are present for each model:**
   - `cleaned_answers.jsonl` → output from the benchmarking pipeline
   - `final_comparison.jsonl` → will be generated by `dataset_remaker.py`
   - `merged_scored_answers.jsonl` → will be generated by `merge_scored_answers.py`

Once added, the pipeline will automatically include all models in the evaluation and comparison steps.
